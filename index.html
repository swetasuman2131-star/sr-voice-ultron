The idea

Two locks, one sentence

A normal voice lock checks one thing. This one checks two at once, so a stolen recording of your words is not enough - the voice has to match too.

Factor 1 — something you know
The passphrase sentence
Your chosen sentence is transcribed and matched against the enrolled text. Say the wrong words and the lock stays shut, no matter whose voice it is.
Factor 2 — something you are
Your voiceprint
A 256-dimension voice fingerprint is compared to the one captured at enrolment. Right words in the wrong voice are rejected.
Optional — proof of life
The liveness code
With --challenge, a fresh random 3-digit code is shown and must be spoken after the passphrase. A recording of a past unlock cannot know a new code, so replay attacks fail.
Under the hood

How it works

One recording goes through five steps. Every step must pass before the lock opens.

STEP 1
Capture
16 kHz mono audio from the mic, or a WAV file
→
STEP 2
Voiceprint
Speaker embedding via resemblyzer (256-d)
→
STEP 3
Transcribe
Offline speech-to-text via faster-whisper
→
STEP 4
Liveness
Spoken code checked against a fresh challenge
→
STEP 5
Decide
All checks pass → UNLOCKED, else LOCKED
Tuning

What it checks, and how strict

Two thresholds control strictness. Raise them for a tighter lock, lower them if you are being wrongly rejected.

CheckWhat it meansDefault
--voice-threshold Minimum voiceprint similarity to open. Same speaker is usually 0.75-0.95; a different speaker 0.50-0.70. 0.75
--text-threshold Minimum sentence similarity. 0.80 tolerates small slips of the tongue. 0.80
--challenge Adds the random digit code you must speak after the passphrase. on in the GUI
--seconds How long each recording lasts. 4
Get started

Install and run

You need Python 3.10+ and a working microphone. Everything runs offline on your machine.

terminal
# 1. get a CPU build of PyTorch pip install torch --index-url https://download.pytorch.org/whl/cpu # 2. install the rest pip install -r requirements.txt # 3. enrol your voice (speak your sentence 3 times) python sr_voice_ultron.py enroll # 4. open the lock - with the anti-replay code python sr_voice_ultron.py unlock --challenge # optional: a small on-screen lock window python sr_voice_ultron.py gui

No microphone handy? Add --from-file clip.wav to any command and it will read a 16 kHz mono WAV instead.

Reference

Commands

Four things you can ask the tool to do.

CommandWhat it does
enroll Set up your voice and sentence. Records you several times and stores the voiceprint in ~/.sr_voice_ultron/.
unlock Try to open the lock. Add --challenge for the liveness code.
status Show what is stored - the passphrase, sample count and enrolment date.
gui A small window with a LOCKED / UNLOCKED indicator and Unlock / Enrol buttons.

Honest limits

Voice biometrics are convenient but weaker than a good password. Know why before you trust one.

It can still be spoofed. The liveness code blocks a replayed recording, but a real-time voice clone - or a live person imitating you - can still fool the speaker model. Strong anti-spoofing needs a dedicated countermeasure model.
Your voice changes. Colds, stress and background noise all shift the voiceprint, so you may occasionally get a false rejection.
The voiceprint is not encrypted. It sits in ~/.sr_voice_ultron/ in plain form. Fine for a home prototype; not for anything sensitive.
This is a demo, not access control. Do not put it in front of anything that actually matters - banking, your OS login, a server.
